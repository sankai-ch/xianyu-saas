## 2026-11-18：暂停自动处理与卡密库存

原版仅在 AI 客服运行时显示暂停按钮，普通规则回复或仅自动发货运行时无法从该入口暂停，而库存修改又要求工作进程停止。

- 在「商品与发货 → 卡密库存」的「批量导入卡密」旁增加「暂停自动处理」。暂停确认明确说明会停止自动回复和自动发货，保留登录信息。
- 暂停后按钮显示「恢复自动处理」，便于补货后恢复。暂停和恢复仍由服务端校验当前用户与店铺，并确认进程状态；不绕过库存写入锁。
- 修复 `Popen.send_signal()` 成功返回 `None` 被当作失败的问题。保留已接管进程句柄返回 `False` 的失败语义。
- 更新页面脚本版本标记，让刷新页面加载修复代码。

操作：暂停自动处理 → 批量导入卡密，每行一个 → 检查可用库存 → 检查商品发货配置。暂停期间不自动回复或发货，补货完成后需要明确恢复店铺运行。

回归检查：`python3 tests/worker-stop-regression.py`。覆盖真实子进程正常停止、忽略 TERM 后强制停止、明确拒绝信号、已退出进程。测试只创建本地短暂子进程，不连接闲鱼、不发送买家消息。

生产配置和库存不放入仓库。官方网页升级会使用上游发布内容，可能覆盖本 Fork 的改动；维护本 Fork 时应从本仓库构建部署。

## 单池库存与实际发货话术

当前每店铺只有一个固定 ID 为 `redeem` 的兑换码库存。原「新建卡密池」实际只修改该池元数据，现改为「卡密池设置」，预填现有名称和备注；批量导入默认选择现有池并锁定名称，避免误认为另建了独立池。导入仍追加、去重，不替换现有库存。

卡密发货在预留订单时保存模板说明，实际消息使用这份已保存话术加订单独立兑换码。因此模板里的测评入口和使用说明会随卡密发送；同一订单重试保留原消息和原码。真实平台订单核验、库存事务与重复通知去重逻辑保留。
